# 客户端

包名：`torse-client`。提供本地交互窗口、离屏PNG输出，以及连接独立服务端的图形客户端。各模式共用场景、网格与绘制管线。

远程连接需要同时提供`--tls-ca`、`--tls-cert`、`--tls-key`及`--server-name`，失败不会退回明文。`--section X,Y,Z`可重复指定用户获准的订阅子集；省略时请求演示范围。回环地址仍支持原本的本地演示。证书配置及双向校验见[用户认证记录](../../benchmarks/M5-user-authentication.md)。

窗口和离屏模式均接受`--memory-mib N`，共享逻辑预算默认512MiB。场景、资源、网络、CPU工作、网格及字形缓存参与同一总量校验；压力下优先释放可重建缓存，拒绝的工作保留意向重试。该预算不等于RSS或GPU显存上限，范围见[共享内存记录](../../benchmarks/M6-shared-memory.md)。

## 运行

在仓库根目录打开本地窗口：

```sh
cargo run -p torse-client -- --window
```

离屏模式输出一张PNG，仍需要GPU与可用的图形后端：

```sh
cargo run -p torse-client -- --capture out.png --width 960 --height 720 --radius 2
```

连接服务端时，先在另一终端创建演示世界：

```sh
cargo run -p torse-server -- .work/client-demo --listen 127.0.0.1:7777 --fill --editors --players 2
```

保持服务端运行，再连接客户端：

```sh
cargo run -p torse-client -- --window --connect 127.0.0.1:7777 --walk
```

`--fill`只适用于新世界，重开同一目录时需去掉。`--editors`授予演示订阅范围内的编辑权限；省略时以访客权限连接，编辑请求会被拒绝。客户端在联网模式中发送意图，服务端提交后通过授权增量更新画面。

`--players 2`提供两个已有玩家，重开时保留该参数。联网行走发送独立的有界输入流，服务端按固定Tick解析碰撞并持久提交，客户端在镜像之外保存预测位置。确认后删除已结算意向，重放尚未确认部分，超出0.05格容差时校正；未订阅到本玩家时停止预测。每连接最多保存64条未确认意向。服务器未分配玩家的连接仍可飞行观察，不能自行创建玩家。

## 参数与操作

| 参数 | 含义 |
|---|---|
| `--window` | 打开交互窗口 |
| `--capture FILE` | 离屏渲染一帧并写入PNG |
| `--width N`、`--height N` | 输出图像或初始窗口尺寸，默认960x540 |
| `--radius N` | 本地分区半径0到16，离屏默认2，窗口默认4 |
| `--view overview`、`--view player` | 离屏相机，默认俯视全景 |
| `--place KEY:X,Y,Z` | 离屏模式先放置一个方块，可重复；用于复现形状与透明检查 |
| `--frames N` | 窗口呈现指定帧数后退出，用于自动验证 |
| `--screenshot FILE` | 窗口正常退出前保存最后一帧 |
| `--autoplay` | 自动前进并周期性尝试破坏或放置方块，会修改世界 |
| `--walk` | 以行走模式启动，自动行走遇台阶时尝试跳跃 |
| `--connect ADDRESS` | 连接服务端并读取授权世界镜像 |
| `--probe-outside` | 联网后发送范围外请求，验证越界拒绝 |
| `--ui-preview hud`、`pause`、`machine` | 指定初始界面，窗口与离屏模式均可使用 |
| `--content DIR` | 加载数据驱动内容包，替代内置演示内容；DIR为游戏仓库根目录或含`atlas.toml`的资产目录 |

WASD移动。窗口聚焦且菜单关闭时隐藏并约束光标，原始鼠标位移用于转向，左右键用于游戏内点击；失焦或打开菜单释放捕获。捕获失败时保留可见光标及原因，可用左键或右键拖动转向。滚轮调整速度。飞行模式下空格上升、左Shift下降；F5切换行走，行走时空格跳跃。短按左键破坏目标方块，短按右键沿选中面放置；数字键1到3切换方块，内置演示场景提供石头、玻璃半砖和植物，内容包场景提供该包里的方块。对可完成半砖的顶面放置时，目标为该格自身，第二块同种半砖合并为一个完整方块。F12保存`torse-shot-N.png`，Esc打开或关闭菜单，E打开机器面板预览。

自动验证示例：

```sh
cargo run --release -p torse-client -- --window --autoplay --frames 2000 --radius 4
cargo run --release -p torse-client -- --window --walk --autoplay --frames 2400 --radius 3
```

退出汇总包含帧数、编辑结果、网络请求、帧时以及CPU任务接纳、取消、过期、背压和预留峰值。窗口中的本地生成与网格共用有界CPU执行器，默认最多4个工作线程、8个在途任务、8MiB输入和32MiB工作及输出预留。脚下一个Section同步装载，其余后台生成；联网场景只构建服务器镜像的网格。离屏模式同步构建，使用与后台相同的网格优化。

每个网格结果校验世界、资源、目标与邻区装载代数及地形修订；离开窗口取消任务，持续编辑合并到最新需求。实现和验证见[有界执行器记录](../../benchmarks/M6-bounded-executor.md)，历史同步测量保留在[帧预算记录](../../benchmarks/M6-frame-budget.md)。

窗口以16666微秒为目标，根据上一帧耗时调节生成、网格和地形上传数量，各自最多4个分区。超时立即降低接纳量，连续8帧有余量后逐级恢复。执行器硬上限继续生效，反馈不改变固定逻辑时钟。地形上传队列合并同分区修改，每帧载荷最多8MiB；超量留待后续帧，卸载和场景替换清理意向。

完整不透明单位方块通过占用行快速跳过遮挡面，同材质、同着色且没有覆盖层的共面行合并。贴图按格重复；半形体、透明面、覆盖层及未加载边界沿用原规则。CPU对照与实际GPU验证见[自适应调度记录](../../benchmarks/M6-adaptive-meshing.md)，不同设备和场景需独立测量。

## 派生光照与透明呈现

窗口增量计算发光和天空光，每次最多推进16384个采样格或传播项，同一时刻保留一个光照工作。缓存、工作区及透明排序元数据纳入共享预算，预算不足时保留待办并重试。离屏模式先在预算内完成光照，再构建网格。

天空光读取到世界顶部的有限高度列，未知分区按不透光处理。本地基础场景因此装载全部四层分区；联网镜像只消费获准数据，缺失上层列时结果保守且不完整，不自动扩大订阅权限。默认单任务最多100万采样格、1024个依赖、100万队列项和16MiB工作区，超限不发布结果。

本地编辑前预留2MiB局部光照预览工作区，每类最多4096次亮度更新。预览从已有亮度传播到新打开的格，不修改权威状态；完整任务仍校验全部依赖后替换。预算不足时编辑在提交前拒绝。原始计算结果和可变呈现副本一起计入每类64MiB缓存上限。内缩面在真实面所在的格采样，避免读取半格空隙另一侧的实心格。

顶点消费发光、天空光和逐角AO。同一物理角在分区边界使用相同邻格；亮度不均匀的面不参与行合并。网格依赖附近的光照版本及AO邻区，过期结果丢弃，远处缓存发布不触发本地重建。透明面跨分区按相机深度排序，深度只读；不透明及裁剪材质先绘制并写深度。

基础内容中完整实心块的吸收率由0修正为1，相应定义版本提升。旧示例世界需新目录或显式迁移，旧离线表需重新生成，不能重写摘要绕过恢复校验。存档及网络格式未改变，光照数据不持久化。验证和限制见[光照呈现记录](../../benchmarks/M6-derived-lighting.md)。

## 逻辑步与呈现帧

窗口用真实帧间隔调用`pump_logic(dt)`，本地行走和自由相机移动统一使用50ms固定步长。每帧最多追赶8步；更长停顿中超出的完整步丢弃，只保留不足一步的余量，不放大单步时间，也不改变权威侧`TickClock`的Tick序列。首帧没有已测间隔，因此不凭空推进时间。

`PresentationClock::presentation_alpha()`给出余量占一步的比例，相机只在两个已完成逻辑位置之间插值。鼠标转向每帧响应一次，追赶多步不会重复应用转向量。`draw`读取相机和场景完成绘制，不推进行走或提交世界事务。网格按地形修订与依赖失效重建，不按Tick插值顶点；分区流式、后台结果接纳和GPU上传仍属于呈现帧，保留现有预算。

菜单打开时冻结本地逻辑与相机插值，网络仍继续接收，服务端重力继续结算。菜单切换丢弃未测的墙钟间隔，恢复后不会追赶暂停时间。出生与模式切换通过`reset_presentation_pose`同步替换两个插值端点并清空相位。频繁网络确认只校正显示姿态，保留逻辑时钟进度，避免持续确认使行走固定步无法触发。网格缓存仍遵守现有“网格/派生缓存”记账类别，呈现时钟和两个位置端点都是固定大小状态。

针对性验证：

```sh
cargo test -p torse-sim --lib presentation::tests --locked
cargo test -p torse-client window::tests --locked
```

## 界面与字体

图集与图标通过资源目录的GUID/句柄解码；实际驻留的mip和图标像素计入资源CPU副本类。调色板克隆共享一份驻留数据，自定义内容包使用自身图集，GPU上传仍由渲染层负责。装载、卸载、预算范围和当前限制见[资源句柄说明](../../crates/assets/README.md)。

窗口默认绘制准星、快捷栏、当前方块和连接状态。菜单提供返回、机器面板预览和退出。面板打开时停止本地移动与编辑输入，网络接收继续运行；联网世界不会因客户端菜单暂停。

界面为程序化绘制的深色扁平主题：半透明深灰面板加一像素边框，按钮分常态、悬停与按下三态，强调色只用于选中的槽位与按下的按钮；窗体、按钮、槽位、进度条与准星都由客户端主题绘制，不再使用皮肤图片。改版记录见[界面主题](../../benchmarks/M1-ui-style.md)。

机器面板明确使用示例数据，目前不读取或修改真实机器与库存。服务端已有机器状态与动作模型，图形客户端对该模型的消费和操作仍待接入。截图及验证见[UI基础](../../benchmarks/M1-ui.md)。

```sh
cargo run -p torse-client -- --window --ui-preview machine
cargo run -p torse-client -- --capture ui.png --width 960 --height 540 --ui-preview machine
```

界面按可用空间选择1到4倍整数缩放。物品图标PNG和文案位于[基础游戏资源](../../games/base/assets/README.md)，编译时嵌入；修改后需重新编译。字体从操作系统读取，可用`TORSE_UI_FONT`指定TTF、OTF或TTC。缺少中文字形时使用英文文案，没有可用字体则报告错误。

## 贴图与材质

地形绘制使用一张纹理图集与固定大小的材质表。内容为每个方块面选择材质键，客户端把材质键解析为图集矩形、色调和混合模式，顶点携带材质槽位；片元着色器按槽位采样图集，乘以色调与逐面亮度，按混合模式处理透明，距离超过阈值后向天空色过渡。地形之前先绘制一层屏幕空间天空渐变，地平线颜色与雾色一致。顶点布局为位置、法线、局部贴图坐标、两个材质槽与两个位置色调，共64字节。

材质表上限512项，内容用到的材质超过上限时启动失败；没有图集条目的材质显示缺失图块。混合模式来自内容定义：不透明与二值透明在片元阶段处理，二值透明按alpha阈值丢弃；半透明面积进入同一绘制通道并开启alpha混合，因此透明面之间没有排序，交叠观感取决于绘制顺序。

图集要求每张图块之间以及图块与图集边界之间至少留一个像素。客户端生成三级mipmap：生成前把图块内透明像素填成最近的实色像素，把边缘向外扩张一个像素，再逐级减半。放大使用最近邻，缩小使用线性过滤并在层级之间线性混合；没有各向异性过滤与纹理数组。二值透明的薄叶片在远处会随层级变细，属于当前限制。

图集与材质条目位于[基础游戏贴图](../../games/base/assets/textures/README.md)。公开的图集解码、材质包校验与mipmap生成在[torse-assets](../../crates/assets/src/texture.rs)，客户端在[texture.rs](src/texture.rs)声明基础游戏的材质包、构建材质表，并在编译期嵌入图集。其他游戏用自有内容键构造`TexturePack`，交给`Scene::with_pack`，再由`GpuContext::set_palette`上传；公开接口不依赖基础游戏的键名。证据与限制见[贴图记录](../../benchmarks/M1-textures.md)。

## 内容包

`--content DIR`从目录读取一份内容描述，替代编译期固定的演示内容。DIR内需要同时存在下面三份文件。

三份文件各管一件事：

| 文件 | 内容 |
|---|---|
| `atlas.png` | 打包后的RGBA图集 |
| `atlas.toml` | 材质键、UV矩形、透明模式、动画帧、mip策略、方块形状与面绑定、群系颜色 |
| `world.toml` | 世界描述：地层方块、水面高度、取色群系、树木与草丛规则 |

加载时把`atlas.toml`转成内核`ContentPack`与`TexturePack`，再据此构建材质表、内容注册表和演示地形。方块键、材质键与群系名全部来自数据，内核代码不出现具体游戏的名字。群系颜色交给位置着色，按方块坐标取样，边界逐格切换。

示例：

```sh
cargo run -p torse-client -- --content path/to/pack --window --radius 3
cargo run -p torse-client -- --content path/to/pack --capture out.png --width 1280 --height 720 --radius 3
```

内容包场景在前台线程生成，半径过大时逐帧变慢；内置演示场景仍走有界后台执行器。快捷栏按世界描述里的方块顺序填充，放不下时再按内容键顺序补足，标签取内容键的路径。树木按列哈希决定，相邻分区各自画出伸进自己范围的部分，因此树冠跨过分区边界也完整。世界描述只覆盖分层地形与散置规则，没有群系选择、地形形状规则或结构生成。

索引中的`model`目前只允许装载元数据。索引不包含模型面数据，客户端不读取包目录以外的几何，因此这些方块使用空视觉模型：**不可见、无碰撞，也不能选取**。装载时会在终端输出受影响的模型数量，并在窗口初始状态中显示预览警告；这不代表已支持完整模型渲染。需要显示模型时，仍须接入真实几何数据及其渲染适配。

`box` 使用显式的 `bounds.min` / `bounds.max` 进行绘制与选取，三轴边界必须有限、位于单格 `[0, 1]` 内，且下界严格小于上界。当前预览加载器不为 `box` 推导碰撞体；缺失或非法边界、给其他形状设置边界，以及未知形状均拒绝整个包。

## 实现入口

| 文件 | 职责 |
|---|---|
| [scene.rs](src/scene.rs) | 内容与世界装配、流式分区、网格、动作提交与行走接入 |
| [background.rs](src/scene/background.rs) | 有界生成与网格任务、取消、背压与结果依赖校验 |

| [game.rs](src/game.rs) | 数据驱动内容包加载、群系位置着色与演示地形 |
| [window.rs](src/window.rs) | 窗口、帧循环、输入调度与网络轮询 |
| [net.rs](src/net.rs) | 握手、订阅、授权镜像与编辑及移动输入 |
| [prediction.rs](src/prediction.rs) | 独立预测状态、有界意向历史与持久确认校正 |
| [input.rs](src/input.rs)、[camera.rs](src/camera.rs) | 输入聚合与相机 |
| [pick.rs](src/pick.rs) | 方块射线拾取与放置面计算 |
| [ui](src/ui/mod.rs) | 界面资源、文字、布局与模态输入 |

本地编辑经过`ActionService`授权和规划，再由`WorldAuthority`提交。本地行走复用`torse_sim::player::walker_step`；联网由`plan_step`规划持久事务，客户端用`predict_step`只读预测。联网编辑与行走均不直接修改镜像，最终状态以服务端持久结果为准。

## 当前限制

- 联网编辑与权威行走已接通，演示仍使用固定范围，自动跟随玩家的兴趣策略尚未装配。宿主可以显式替换批准范围，客户端可以退订后请求新基线。
- 实体以色块呈现，行走玩家由相机表现，联网玩家持久化，本地行走实体不持久化。嵌入地形的联网实体会拒绝移动并要求校正，需由可信宿主调整位置。
- 放置不消耗库存，破坏不生成掉落；机器面板仍为预览，真实库存图形操作尚未接入。
- 拾取把非空格按完整立方体处理。内置演示场景只装载`y = 0`分区层，内容包场景按世界描述可能达到的高度装载一到四层。
- 地形使用图集贴图、三级mipmap、逐面亮度与距离雾，天空为屏幕空间渐变；没有太阳、云、阴影、环境光遮蔽、透明排序、各向异性过滤、自动上台阶或水体物理。
