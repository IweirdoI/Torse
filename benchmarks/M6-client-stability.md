# 客户端光照连续性与输入修复

## 问题与处理

光照观察失效后立即移除缓存，会让重建中的网格把缺失亮度当作零，造成编辑和分区流送时的黑闪。客户端现在保留上一份完整的呈现数据，只有完整计算并通过当前世界校验的新结果才能替换它。未完成首次光照计算时沿用方向光着色；已经计算得到的零仍显示为黑暗。

保留旧亮度仅用于画面连续性，不参与碰撞、权限或权威查询。卸载、重新加载目标及世界纪元切换会清除对应数据。工作区仍限16MiB，发光和天空光各限64MiB缓存，预算不足保留旧画面和待办；替换期间新旧两份数据均计费。

依赖验证集中到每次光照更新，网格凭据不再重复遍历整套光照依赖。光照像素未变时保留呈现版本。面光照只读取自身及六个相邻分区，AO仍观察完整邻区。采样直接借用缓存，不为每项网格任务复制完整缓存索引。

HUD和菜单内容未变化时复用已上传的纹理，窗口尺寸、菜单、悬停、按下状态或显示内容变化时重新绘制。捕获鼠标使用原始设备位移，移除光标反复居中、丢弃下一次事件及小位移阈值；失焦、菜单和未捕获状态仍不转动视角。

## 验证

```sh
cargo test -p torse-client --locked
cargo test -p torse-client --features gpu-tests --locked
cargo test --workspace --locked
cargo clippy --workspace --all-targets --locked -- -D warnings
cargo run --release -p torse-client --locked -- --window --frames 1800
cargo run --release -p torse-client --locked -- --window --frames 2400 --autoplay
cargo run --release -p torse-client --locked -- --window --frames 2400 --walk --autoplay
```

新增回归覆盖光照失效期间的亮度保持、相同亮度重算不变更呈现版本、首次计算前的方向光，以及原始鼠标微小位移、连续事件累计和失焦菜单限制。既有光源移除测试继续要求最终变暗，预算恢复、场景纪元和释放测试继续通过。

客户端113项测试通过；启用实际GPU测试后115项通过，其中2项检查Vulkan像素及GPU预算行为。工作区903项测试通过，保留1项既有计时测试的默认忽略设置；Clippy及格式检查通过。

## 窗口记录

环境为Windows、Release构建、RTX4060LaptopGPU、Vulkan和Mailbox，默认324个分区。窗口截图验证HUD、选中轮廓及地形仍正常绘制。[原始计数](data/client-stability/01-release/metrics.csv)记录各次运行。

| 场景 | 帧数 | 平均帧耗时 | 最大帧耗时 | 网格重建 | 上传 |
|---|---|---|---|---|---|
| 修复前短测 | 1801 | 4399us | 18249us | 3232 | 3023 |
| 修复后短测 | 1801 | 2456us | 26661us | 442 | 347 |
| 自动移动与编辑 | 2401 | 2986us | 15042us | 2655 | 2394 |
| 自动行走 | 2401 | 3037us | 15772us | 700 | 581 |

自动编辑成功101次，无拒绝；行走完成149个固定步并跨越分区。修复后的运行内存峰值低于160MiB，GPU几何均低于默认64MiB限制。

这些是单机短测，包含冷启动、后台任务及最终截图。修复前的光标事件还改变了视角，两个短测的可见分区数不同，不能据此承诺固定FPS或将差值全部归因于某个改动。最大帧耗时也没有稳定下降。持续编辑仍需要重新计算地形和光照，增量光照的完成时间取决于工作量与预算。

## 兼容范围

仅修改客户端呈现、缓存与输入实现，存档、网络、WIT和权威组件布局不变。宿主没有新增权限或迁移要求。鼠标捕获先尝试锁定，平台不支持时使用窗口约束；两种模式都失败则保留可见光标及原有拖动操作。
