# 验证与测量记录

本目录保存各次验证的复现命令、运行环境、画面、测量结果与未覆盖范围。记录中的日期和代码状态决定其适用范围；早期记录里尚未实现的能力，可能已由后续记录补齐。当前使用方式见[项目README](../README.md)和各应用说明。

图形客户端已移出内核仓库；涉及窗口与界面的记录保留为当时内核能力的测量数据，其中的`apps/client`路径不再有效。

现有资料主要验证正确性与故障处理。[帧预算记录](M6/M6-frame-budget.md)包含指定设备上的Release对照测量，尚未建立覆盖不同设备、规模和负载的统一性能基准。

## 目录结构

| 路径 | 内容 | 规则 |
|---|---|---|
| `README.md` | 索引与目录规范 | 新增记录后补一行索引 |
| `<批次>/<批次>-<主题>.md` | 单次验证与测量记录 | 按批次前缀分目录，`README.md`留在根目录 |
| `data/<场景>/` | 原始测量数据 | 按场景分目录，保留环境与运行编号 |
| `figures/NN-<主题>.png` | 编号图 | 两位序号，按首次引用顺序递增 |

报告按批次前缀分目录，`README.md`留在根目录作为索引；数据与图仍各自独立存放，避免把二进制和正文混在同一层。子目录只按批次分组，不再按主题细分。

## 命名

| 类型 | 规则 | 示例 |
|---|---|---|
| 报告 | `<批次>/<批次>-<主题>.md` | `M6/M6-frame-budget.md` |
| 批次前缀 | `M0` 到 `M6`、`A`、`B`、`CLN`、`ENG` 系列 | `A8-acceptance.md` |
| 数据目录 | `<场景>/<NN>-<变体>/` | `data/incremental-projection/01-before/` |
| 环境文件 | `environment.txt` | 设备、系统、工具链 |
| 图 | 新图 `NN-<主题>.png`，旧记录沿用原文件名 | `figures/09-slab-merge.png`、`figures/M1-actions.png` |

主题用小写英文和连字符，不复述批次；同一场景的对照运行用两位序号区分。

## 记录类型

| 类型 | 内容 |
|---|---|
| 测量 | 有对照数据、环境与可复跑命令的性能、资源或帧时记录 |
| 验收 | 功能正确性、场景覆盖、拒绝与恢复记录 |
| 实验 | 技术可行性探索，不代表长期基线 |

## 记录格式

每份记录以唯一的 H1 开始，头部字段固定为：

```text
# 标题

日期：[20261029]
类型：测量
状态：已验收
环境：Windows 11 x86_64，Rust 1.93.1，release
范围：客户端帧时与流式加载
```

日期使用`[YYYYMMDD]`。`类型`取`测量`、`验收`或`实验`；`状态`取`已验收`、`待复验`、`已废弃`或`未记录`。无法确认的历史环境写`未记录`，不要补猜测内容。

正文按以下顺序组织：

```text
## 目标
## 方法
## 结果
## 复现
## 边界
```

`画面`与`后续`为可选章节。旧记录中的其他章节标题统一并入上述章节，不再新增同义的顶层标题。

| 章节 | 内容 |
|---|---|
| 目标 | 本次验证要回答的问题、范围或缺陷 |
| 方法 | 改动、场景、配置与判断依据 |
| 结果 | 测量、输出、判读与验收结论 |
| 复现 | 可直接执行的完整命令 |
| 边界 | 没测的设备、模式、版本与失效条件 |

测量记录的结果必须保留原始数据路径；验收记录的结果必须列出场景与通过或拒绝的判定。只写结论而不留证据的记录不合格。

## 新增流程

1. 运行场景，把原始输出放到 `data/<场景>/`，并写 `environment.txt`。
2. 截图或图表放到 `figures/`，按顺序编号。
3. 在根目录写报告，套用上面的记录格式。
4. 更新本文件索引，放到对应分组。
5. 不改旧记录的数字与结论；新的对照另起记录，并在旧记录里补一行指向新记录。

## 图文件

截图统一放在 `figures/`。新图用两位序号命名，旧记录沿用原文件名（如 `figures/M1-actions.png`），不再散落到报告目录。报告里引用图时写相对路径 `figures/<name>`。
