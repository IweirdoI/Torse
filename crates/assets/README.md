# 资源句柄与CPU驻留

`AssetCatalog`提供issue #6的第一版同步装载、显式卸载与资源类记账契约。它管理目录拥有的CPU字节副本；PNG解码和材质校验仍在`texture`模块，GPU上传与GPU生命周期仍由渲染层负责。

## 身份与访问

- `AssetGuid(u128)`由宿主分配，不从文件内容、世界实体ID或方块`ContentKey`推导。
- `AssetAlias::Key`与相对路径别名用于查找GUID，再通过`handle(guid)`取得当前驻留句柄。路径校验也在装载边界执行，直接构造枚举不能绕过校验。
- `AssetHandle`包含GUID和代际，只能用于发放它的目录。宿主跨场景传递任务时仍需保留目录/世界epoch；持久身份是GUID，不是运行期句柄。
- `asset_generation()`是目录的单调修订。新装载与卸载推进修订，同字节、同依赖的重复装载返回原句柄。卸载后重装取得新代际，旧句柄不能读取新副本。

代际取自目录的单调修订，不为每个已卸载GUID永久保存墓碑。代际耗尽返回资源限制错误，目录和账本保持不变，不回绕或复用旧代际。

## 依赖与失败

依赖使用GUID，必须先装载；依赖列表按集合处理。仍被驻留资源依赖的副本不能卸载。同GUID的字节或依赖发生变化时必须先卸载再装载，不能静默改变依赖图；第一版不做热更新。

单次`load`/`unload`因无效路径、别名冲突、缺失依赖、陈旧句柄、被依赖或预算不足而失败时，不修改目录、代际或账本。相同字节与依赖的重复装载不增加别名或引用次数。

`MemoryBudget`限制一个目录中的CPU载荷字节，计入`MemoryClass::Resource`。卸载释放目录拥有的字节与对应收费。别名和索引是目录元数据；该账本不是全局分配器，也不代表整个进程所有堆内存的上限。

## 客户端接入

内置PNG仍可作为编译期源数据；图集与图标解码从源目录通过GUID/句柄读取，源目录在同步解码后释放。卸载不会移除可执行文件内的只读源字节。

实际用于GPU上传的图集mip像素驻留在调色板目录中，渲染层按句柄借用它们。调色板克隆通过`Arc`共享同一目录与一份收费，最后一个所有者释放时回收CPU副本。场景的`asset_generation`来自实际调色板，自定义内容包不会额外登记或常驻基础游戏图集。

UI的解码图标同样由资源目录持有，绘制时通过句柄读取。客户端默认每个调色板/图标目录的CPU载荷上限为8MiB；多个目录的用量不能被当成一个全进程总上限。字体、临时解码缓冲和GPU分配不计入此目录。

运行期派生mip标识仅用于所在调色板的私有目录，不是煮熟表的跨包身份。煮熟表格式、异步流式、跨进程仓、音频/模型，以及完整的场景运行时资源替换不在本版范围内。

## 验证

```sh
cargo test -p torse-assets --locked
cargo test -p torse-client --locked
```

回归覆盖陈旧句柄、依赖卸载保护、依赖变更拒绝、直接构造的非法路径、预算和别名失败无副作用、代际耗尽，以及实际mip像素收费与调色板克隆共享。
