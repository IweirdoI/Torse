# 持久化

包名：`torse-storage`。B2、B3已实现日志、检查点发布与读取、有界容量和恢复扫描。领域接入使用测试模型验证，真实世界文件恢复仍待B5领域编码与B6装配。

| 文件 | 职责与状态 |
|---|---|
| [journal.rs](src/journal.rs) | CommitJournal、预留令牌、有界队列、文件创建与重开 |
| [backend.rs](src/backend.rs) | 有界内存后端、文件后端、可注入失败的追加与同步接口 |
| [recovery.rs](src/recovery.rs) | 逐条验证包裹、载荷、世界、兼容信息与连续提交位置 |
| [checkpoint.rs](src/checkpoint.rs) | CheckpointStore、发布状态机、读取与显式清理 |
| [checkpoint_backend.rs](src/checkpoint_backend.rs) | 内存与文件检查点后端、独立同步边界和故障注入接口 |
| [manifest.rs](src/manifest.rs) | 固定宽度manifest编码、完整前缀校验与位置检查 |

## 日志行为

`MemoryJournal`与`FileJournal`共用`Journal`状态机。初始化显式传入Binding、可信检查点位置、具体StorageCodec和JournalConfig，不提供无界默认值。内存后端另设累计保留字节上限，超限按存储失败处理；其同步结果仅表示当前进程内可读取的完整前缀。

`try_stage`检查世界、兼容信息和下一序号，完成有界编码，预留条目与帧字节容量。一次只允许一个未消费令牌，与契约中的单准备项一致。Staged不可复制，内部绑定实例、Binding和位置；丢弃释放容量，序号可重试。

`accept`只移动已经预留的缓冲。队列槽位在构造时分配，接纳不进行编码、I/O或队列扩容。错误实例或旧实例令牌属于终止性故障。宿主必须在A发布后立即接纳令牌，并在`flush_through`成功后才公开对应结果。

`flush_through`按顺序写到目标位置，再执行同步屏障。文件后端使用`write_all`与`sync_all`。任一失败后停止实例，保留此前DurableSeq，释放待写缓冲；后续操作失败，必须通过新实例恢复。目标未被接纳或属于其他世界时返回输入错误。

## 容量与恢复

JournalConfig同时限制待写条目数、帧总字节、单记录编码预算和帧载荷上限。单记录无法放入空队列时返回TooLarge；暂时被其他记录占用时返回Busy。编码期间另有至多两个受单记录上限约束的缓冲，字节限额按有效数据长度计算，分配器开销另计。

`scan_journal`逐条读取完整帧后解码，通过回调交给独立恢复构建器。回调接收到坏记录前的完整前缀，后续任意失败时调用方丢弃整个构建器。扫描限制单帧和单条解码分配，总世界预算由A的构建器控制。

扫描结果包含最终位置、有效字节数、完整记录数和不完整尾部标记。跳号、重复、完整记录损坏、错误世界和兼容不符均失败，错误包含字节偏移。文件重开先扫描，只有扫描成功后才截去不完整尾部，同步有效前缀，再继续追加；损坏或预算不足时保持文件内容。

文件实例持有排他文件锁，创建采用`create_new`，避免覆盖既有日志。apps/server持有B4世界目录锁。B2不删除已覆盖日志；初始空日志及已有世界根目录中的目录项由服务端生命周期同步，上级根目录的首次持久发布仍由宿主负责。

## 检查点发布

`Checkpoints<M, C, B>`实现契约中的`CheckpointStore`，提供MemoryCheckpoints与FileCheckpoints别名。配置必须显式限制领域编码与解码预算、帧大小、manifest总字节和快照文件数。内存后端另有累计保留字节上限。

宿主在Tick边界暂停，先把日志同步到快照位置C，再捕获完整有限世界，传入同一Binding的Durability。存储检查世界、兼容信息、运行代数、`C <= DurableSeq`和位置不回退；首次发布必须为位置0。世界捕获是否完整及ResumePoint是否为Tick边界由A与宿主负责，通用存储保留阶段和步骤原值。

发布顺序为编码及解码预检、创建新一代快照、同步快照、读回验证包裹与领域元数据、追加manifest记录、同步manifest，最后更新当前检查点。发布不修改旧快照。开始写入后的任何失败都会停止实例，必须重开；失败可能留下孤立快照、半条manifest或完整的新manifest。

文件后端接收已存在的专用目录，持有manifest排他锁。快照使用`create_new`，manifest追加发布，完整布局见[FORMAT.md](FORMAT.md)。重开先检查完整manifest前缀和最新引用的快照，成功后才截去不完整尾部并同步。完整损坏、快照缺失及元数据不符均报错，保留原文件，不自动选择旧检查点。孤立文件的代号会被跳过，避免重用。

B4增加`Checkpoints::inspect`与`activate`，用于分离只读检查和尾部修复。inspect允许读取当前快照，禁止发布与清理；宿主完成独立领域恢复后才activate，修复不完整尾部并同步。activate失败停止实例，重复成功激活不产生额外操作。原open继续完成检查与激活两步，保持B3调用方式。

## 保留与清理

`prune(retain)`单独执行，至少保留一代。它再次验证当前检查点，按manifest代号与提交位置保留最近的已发布快照，删除更旧快照和未发布的孤立文件。清理失败停止实例，当前快照始终保留。目录只接受约定名称的普通文件，其他文件会触发错误。

返回的`log_floor`是实际保留检查点中的最早提交位置，恢复仍需保留其后的连续日志。当前日志是单文件，B3保留全部日志，不按文件时间或快照发布时间删除日志。未来支持日志分段后，才可据此回收已被所有保留检查点覆盖的段。历史manifest仍保留已清理快照的引用，最新完整记录仍是唯一自动恢复入口。

manifest记录保存发布时已知的DurableSeq。宿主恢复时须检查检查点与日志的完整前缀至少覆盖该位置，再交给独立构建器完成恢复；manifest发布之后新增的持久提交仍需后续生命周期记录其恢复预期。manifest达到配置上限后拒绝发布，当前未提供压缩或自动扩容。

## 验证边界

[日志测试](tests/journal.rs)覆盖内存与真实文件行为、预留释放、容量、令牌误用、逐字节部分写入和刷盘失败。[恢复测试](tests/recovery.rs)覆盖截断、位翻转、跳号、插入删除、碎片读取、I/O失败、预算、未知字节往返及重开失败保留原文件。

[检查点测试](tests/checkpoint.rs)覆盖发布顺序、固定字段布局、位置与身份错误、容量、逐字节manifest尾部截断及部分追加、完整损坏、快照缺失、保留与清理、同步失败和五个实际子进程退出边界。包含测试模型的检查点与日志后缀恢复组合，未接入A的真实恢复构建器。

当前已在Windows与Rust1.93.1上验证。文件屏障调用`sync_all`；Unix实现另同步目录，尚未在Linux实机运行。Windows已验证突然退出后的重开，硬件断电及具体文件系统的目录项持久性尚未验收。内存后端只保证调用方保留的数据在进程内可读。世界目录锁和初始数据文件同步已在apps/server实现，完整世界领域恢复及上级根目录发布仍需后续宿主装配。
